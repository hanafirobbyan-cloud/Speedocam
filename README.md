# SpeedoCam — iPhone motorcycle dashcam (PWA)

SpeedoCam turns an iPhone into a motorcycle dashcam. It records the road with the camera and **burns a live GPS speedometer into the video frames** (speed, unit, limit warning, max speed, recording time, date/time, GPS status). It is a Progressive Web App: no App Store, no build step, hosted on GitHub Pages, installed from Safari with *Add to Home Screen*.

- Plain HTML/CSS/JavaScript (ES modules). No framework, no dependencies, no build.
- Works offline once installed (service worker).
- Video, GPS tracks and settings never leave the phone.

---

## Features

| Area | What you get |
| --- | --- |
| Recording | Start / Pause / Resume / Stop, live duration, file size and effective FPS, camera status. 1080p60 when the device delivers it, automatic fallback otherwise. Clips split every 3/5/10 min (optional). |
| Burned-in overlay | Speed + unit, optional limit badge and red over-limit warning, optional max speed, REC time, date & time, optional GPS status. Digital or dial style, 4 colors, 3 sizes, left/right placement. Drawn on the exact camera frame it belongs to. |
| Speedometer | Large live speed, arc gauge with limit tick, MAX / AVG (moving average) / GPS accuracy, km/h ↔ mph with one tap, per-unit speed limits. |
| GPS honesty | Device (Doppler) speed preferred; speed hidden as `--` when accuracy is worse than 50 m or no fix for 4 s; spikes > 1.5 g held; only good fixes can set the max. |
| Storage | IndexedDB, written chunk-by-chunk every second while recording; interrupted clips recovered on next launch; loop recording (delete oldest unprotected clips when space runs low); protect clips. |
| Export | Share sheet (*Save Video* → Photos), download, **GPX track** and **SRT subtitles** synced to the video timeline. |
| iOS handling | Wake lock, auto-save + auto-resume when iOS backgrounds the app or a call takes the camera, auto-pause while the camera is interrupted, clear permission guidance, update banner that never interrupts a recording. |
| Device test | Measures which camera modes the phone really delivers, records a 4 s test clip and measures its real playback FPS, shows GPS source/accuracy/update rate. |

### How the pipeline works

```
Camera (getUserMedia) ──► <video> ──requestVideoFrameCallback──► Compositor canvas
GPS (watchPosition) ──► SpeedEstimator ──► overlay state ──► OverlayRenderer ──┘ (blits cached band)
Compositor canvas.captureStream(fps) ──► MediaRecorder (MP4/H.264) ──1 s chunks──► IndexedDB
                                          GPS samples, timestamped on the video timeline ──┘
```

- **Frame sync:** the compositor draws on every camera frame (`requestVideoFrameCallback`) and paints the overlay state *at that moment* onto that frame, so the overlay is permanently part of the pixels. The overlay band is only re-rendered when its visible text changes (~1–2×/s); each frame just blits it, which keeps 60 fps affordable.
- **GPS ↔ video sync:** each GPS sample stores `t` = position on the clip's timeline (paused time excluded) plus the fix's own timestamp. The GPX/SRT exports use these, so subtitles line up with the video.
- **Crash safety:** MediaRecorder runs with a 1 s timeslice and each chunk is committed to IndexedDB immediately. If iOS kills the app, the clip is marked *recovered* on next launch.

## Deploy to GitHub Pages

HTTPS is required for camera and location access; GitHub Pages provides it.

1. Create a new repository on GitHub (e.g. `speedocam`) and push this folder:
   ```bash
   git init
   git add .
   git commit -m "SpeedoCam PWA"
   git branch -M main
   git remote add origin https://github.com/<you>/speedocam.git
   git push -u origin main
   ```
2. On GitHub: **Settings › Pages › Build and deployment › Source: GitHub Actions**.
3. The **Deploy to GitHub Pages** workflow runs on every push to `main` (or run it manually from the Actions tab). When it finishes, the app is at `https://<you>.github.io/speedocam/`.

All paths are relative, so the app works from any sub-path (and on any other static HTTPS host such as Netlify, Cloudflare Pages or Vercel — just serve the repository root).

### Updating the app

Push to `main`. The workflow:
1. checks that every app file is in the service-worker precache list (`tools/check_assets.py`),
2. stamps the commit SHA into `sw.js` and `js/app.js`,
3. deploys.

Installed apps notice the new service worker the next time they come to the foreground and show **"A new version is ready — Update"**. The update is never applied during a recording. If you add a new file under `js/`, `css/` or `icons/`, add it to `ASSETS` in `sw.js` (the workflow fails otherwise).

## Install on iPhone

1. Open the GitHub Pages URL in **Safari**.
2. Tap **Share › Add to Home Screen › Add**.
3. Open **SpeedoCam** from the Home Screen and tap **Enable camera & location**. Allow both.
4. Open **Settings › Device test** and run *Test camera modes* and *Run 4-second recording test* once. This tells you whether your phone records 1080p60 with the overlay; pick the quality it recommends.

Recommended iOS settings while riding: a charging mount, **Auto-Lock: Never** (Settings › Display & Brightness) as a backup to the app's wake lock, and Low Power Mode off (it caps the camera frame rate).

## Local development

```bash
python3 tools/serve.py
```

Open <http://localhost:8765/> (localhost counts as a secure context, so a desktop browser's webcam and location work). Run the tests at <http://localhost:8765/tests/>.

The dev server disables caching and the service worker uses network-first on `localhost`, so edits show up on reload.

### Testing on an iPhone during development

iOS requires real HTTPS for camera and GPS. Options:
- Push to a branch and deploy (the simplest; the test suite is deployed too at `/tests/`).
- Or expose the dev server through an HTTPS tunnel, e.g. `cloudflared tunnel --url http://localhost:8765`, and open the tunnel URL in Safari.

## Testing & validation

### Automated (browser test suite — `tests/index.html`)

32 tests covering: unit conversions and locale defaults; formatting; settings validation/persistence/per-unit limits; GPS speed logic (device vs computed speed, accuracy gating, stale-signal loss, cached-fix rejection, spike hold, permission denial); trip stats (moving average, gaps, untrusted samples); SRT/GPX exports; recording bitrate/output-size rules; camera constraints; overlay text, rendering in landscape/portrait for both styles and all sizes, over-limit red state, band caching; IndexedDB chunk round-trip/order/delete; and an end-to-end pipeline test (compositor → MediaRecorder → IndexedDB → playback) that checks pause time is excluded from the clip and samples, and that the overlay is present in the **decoded pixels** of the recorded file.

The pipeline test uses a synthetic canvas video as its "camera". That exists only on the test page; the app itself never uses simulated video or GPS data.

Status of this build: **32/32 passing in Chromium** (desktop). Run the same page in Safari on your iPhone after deploying — it is the authoritative result for iOS.

### On-device checklist (iPhone, Safari / Home Screen app)

These need a real iPhone and cannot be verified from a desktop:

| Check | How |
| --- | --- |
| Camera access | First launch prompts; camera pill shows e.g. `1080p · 60 fps`. |
| 1080p60 capability | Settings › Device test › *Test camera modes*: the "FPS rep./meas." column shows reported vs measured frames. |
| Recording FPS with overlay | Device test › *Run 4-second recording test*: "Recorded file (played back)" FPS. If below target, choose 1080p30. |
| GPS speed accuracy | Ride (as a passenger) or drive at a steady speed and compare with the vehicle speedometer; Device test › GPS shows source *Device (Doppler)* and ~1 s update interval. |
| Overlay sync | Record, then scrub the clip in the player: speed/time in the frame should match the moment; the SRT export should line up too. |
| Unit switching | Tap the unit under the speed; the gauge, limit and overlay switch instantly. |
| Speed-limit warning | Set a low limit (e.g. 10) and move faster: speed and gauge turn red; with *Show limit in video* the recorded panel turns red. |
| Playback & export | Recordings › clip › *Save / Share › Save Video* → appears in Photos; *Download* → Files. |
| Interruptions | During recording lock the screen / switch apps / receive a call: the clip is saved, and recording resumes in a new clip on return (Auto-resume). |
| PWA install | Add to Home Screen; launches full-screen without Safari UI; works in Airplane Mode after the first launch. |

## iOS limitations (and what the app does about them)

| Limitation | Workaround in SpeedoCam |
| --- | --- |
| **No background recording.** iOS suspends web apps and stops the camera when the screen locks or another app/call/Siri takes over. | Clip is finalized immediately; on return a new clip starts automatically (Auto-resume). Wake lock keeps the screen on; set Auto-Lock to Never as a backup. *Ride display* blacks out the preview to save power while recording. |
| **1080p60 is not guaranteed.** Safari chooses the camera mode; canvas compositing + encoding at 60 fps can drop frames on older iPhones or when hot. | `Auto` requests 1080p60 and takes the closest mode the camera delivers; the device test measures real output FPS; 1080p30 / 720p presets available. The rec pill shows the live drawn FPS. |
| **Videos live inside the app**, not in Photos. Safari and the Home Screen app have separate storage; deleting the app deletes its data. | *Save / Share › Save Video* copies a clip to Photos. Persistent storage is requested. Loop recording and storage warnings prevent "disk full" surprises. |
| **GPS ≈ 1 update/s** for web apps; no speed-accuracy value is exposed. | Device (Doppler) speed is used, low-accuracy and stale readings are hidden (`--`), spikes are held, max speed only from good fixes. The overlay shows GPS status. |
| **Screen orientation cannot be locked** by a web app. | Recording size is locked when a clip starts; rotating mid-clip letterboxes instead of cropping or corrupting the file. |
| **No vibration API** on iOS. | Warnings are visual (red speed, red gauge, red badge). |
| **Variable frame rate** MP4 from MediaRecorder. | Plays everywhere (Photos, QuickTime, editors); editors may convert to constant frame rate on import. |
| **Chunked saving depends on the browser.** Some MediaRecorder builds only flush data at keyframes or on stop. | The device test reports how many chunks arrived during 4 s. If it says 1, use short clip splitting so less footage is at risk. |
| **Wind noise** makes microphone audio mostly useless on a bike. | Audio is off by default; enable it in Settings. |

**Raw mode alternative:** if your phone cannot sustain the overlay at the frame rate you want, set *Settings › Overlay: Off (raw camera)*. The camera stream is recorded directly (no canvas cost) and the speed is exported as **SRT subtitles / GPX**, which players and editors (e.g. VLC, DaVinci Resolve, telemetry-overlay tools) can render on top.

## Privacy

Everything stays on the device: video in IndexedDB, settings in localStorage, no analytics, no network requests other than loading the app itself.

## Safety

Set up the app while stationary. Do not interact with the phone while riding. Speed readings are for reference only — follow posted limits and your vehicle's speedometer.
